# 演示版实施计划

> 本页是第一版（演示版）的总计划：目标、里程碑、任务拆分、排期、分工、风险与完成定义。进度实录只写 [[00-当前系统状态]] 与各阶段页，本页不随每日进展改写。

## 一、总目标与交付物

一句话：**用合成数据 + 占位模型，把「检测 → 跟踪 → 时序风险 → 分级告警 → 人工处置 → 事件回溯」在主链路上一台机器跑通，并可按剧本完整演示。**

| 交付物 | 形态 | 验收标准 |
| --- | --- | --- |
| 可运行系统 | Docker Compose 一键起 5 个服务 | `docker compose up -d` 后 3 分钟内可登录 |
| 演示脚本 | Markdown + 5 个注入剧本 | 剧本下强告警在 30s 内出现且可复现 |
| 源码与说明 | `stages/` 五个阶段 + README | 每阶段 README 能独立指导启动 |
| 设计文档 | 需求、选型、架构、契约、数据模型 | 与代码一致，无「文档有代码无」 |
| 演示材料 | 截图、录制、答辩提纲 | 存 `artifacts/`，对应一条运行记录 |
| 模型接入说明 | 一页替换指南 | 只改 provider + 配置即可接真实权重 |

## 三、任务拆分

### M1 · 契约与骨架

- 冻结 [[01-项目调研规划与开发建设记录/01-第一版-演示平台/03-架构设计/02-接口契约]] 与 [[01-项目调研规划与开发建设记录/01-第一版-演示平台/03-架构设计/03-数据模型]]。
- Flyway 建表 + 种子数据；后端统一包络、异常处理、JWT、RBAC。
- 模拟数据源：游客生成器、游动轨迹、手环生理、水质漂移，按固定 `seed` 可复现。
- 前端：Vite 工程、路由与布局、登录页、8 个空页面、Axios/WS 封装。
- 联调：`/live/snapshot` 先返回合成数据，验证前后端链路通。

### M2 · 实时监控

- 合成画面渲染器：泳池底图、泳道、区域半透明填充、泳者精灵图（4 帧动画）。
- 叠加层：检测框、`track_id` 标签、姿态色标、风险分环。
- WS `frames` 推送节流（≥25 帧/秒按 50 ms 合批），前端 requestAnimationFrame 插值。
- 断线重连 + 快照补拉 + 顶部降级横幅。
- 风险分展示：目标悬浮卡（头部出水时长、静止时长、规则命中）。

### M3 · 告警闭环

- 后端告警状态机：`OPEN → ACKED → DISPATCHED → RESOLVED`，旁路 `FALSE_ALARM`。
- 去重合并（60s 窗口同目标同区域）、超时升级（WEAK 30s → STRONG）。
- 告警中心页：列表 + 详情 + 处置表单 + 时间线。
- 事件回溯：风险曲线、轨迹热区、片段播放（复用合成画面渲染器按时间戳回放）。
- 导出任务（CSV 先做，PDF 留 P1）。

### M4 · 围栏·手环·看板

- 围栏绘制：Canvas 多边形取点、拖拽顶点、命名、适宜人群、豁免规则。
- 越界判定：点是否在多边形内 + 持续时长；区分「误入浅水区」「儿童进入深水区」。
- 手环：目标↔手环绑定面板、心率/血氧/静止三指标、交叉验证规则可配。
- 看板：人数与密度、区域热力矩、行为趋势、峰谷柱图（ECharts 按需引入）。

### M5 · 设备水质与算力调度

- 设备健康：在线、镜头清洁度、防水密封、供电四指标 + 维护记录。
- 水质：水温/浑浊度/pH/余氯曲线与阈值；超标提示维护并在大屏提示「检测精度可能下降」。
- 算力档位：高峰/低谷参数模板、切档接口、指标曲线（延迟、算力占比），全部标注「模拟值」。

### M6 · 演示打磨与交付

- 演示控制台：剧本选择、时钟倍速、故障注入、一键重置（清库重建 + 重置跟踪器）。
- 五条剧本编排成一条 8 分钟主线：正常 → 停留 → 静止下沉 → 强告警 → 手环异常 → 处置 → 回溯 → 切档。
- 文档定稿、录屏、答辩提纲、软著材料清单。
- 交付检查：冷启动计时、重置后一致性、日志与 `run_id` 留存。

## 六、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 前端合成画面性能不足 | 掉帧、演示卡顿 | 精灵图预渲染 + Canvas 分层（底图离屏缓存）+ 只重绘脏区 |
| 契约反复变更 | 前后端返工 | 契约先冻结，改契约必须先改文档并通知；用 mock 服务支撑前端并行 |
| 告警风暴/重复告警 | 页面刷屏，演示失真 | 去重键 + 冷却窗口 + 分级限流，前端合并同类项 |
| 时间不够做完全部 P0 | 演示不完整 | 严格 P0/P1 划分，P1 全部可砍；M3 结束即具备最小可演版本 |
| 模型接入改动大 | 二次返工 | `Detector` 接口从 M1 就定死，占位与真实实现同一签名 |
| 演示环境不稳定 | 现场翻车 | 交付前做 3 次冷启动彩排；准备离线镜像与失败回退话术 |
| 数据重置不干净 | 每次演示起点不同 | 一键重置 = 清库 + 重建 + 重置跟踪器 + 固定随机种子 |
| 口径夸大 | 答辩被质疑 | 全站「占位模式」标识；指标页标注「申报书目标值 / 模拟值」 |

## 七、完成定义（DoD）

每个里程碑收尾必须同时满足：

- 该阶段功能在本机按 README 步骤可复现启动。
- 契约文档与实际接口一致（字段、枚举、错误码）。
- 该阶段「测试与交付」笔记完成，含实际测试记录与未完成项。
- 问题与解决写入独立问题记录页，且没有阻塞项。
- 笔记校验脚本通过。
