# S01 · 问题记录与解决方案

> 本阶段实际遇到的错误与处置。每条含现象、原因、影响、解决办法、验证结果、状态。

## 一、镜像拉取失败（跨阶段前置问题）

| 项 | 内容 |
| --- | --- |
| 现象 | `docker pull` 报 `EOF`；直连 `registry-1.docker.io` 超时 |
| 原因 | 远端无 Docker Hub 出口；国内加速器的 blob 落在境外 CDN；Clash 节点当时不可用（境外 502） |
| 影响 | 无法构建任何业务镜像，M1 阻塞 |
| 解决 | 修好节点后，把 Docker 引擎代理指向 `http://192.168.111.234:7897`，**配置文件必须用小写键名** `proxyHttpMode` / `overrideProxyHttp` / `overrideProxyHttps` |
| 验证 | `hello-world`、`mysql:8.0`、`nginx`、`temurin`、`maven`、`python`、`node` 全部拉取成功 |
| 状态 | 已解决（细节见 [home-dev 说明](../../../../../deploy/home-dev/README.md)） |

## 二、代理配置写成 PascalCase 不生效

| 项 | 内容 |
| --- | --- |
| 现象 | 写入 `ProxyHTTPMode` 等大写键后，引擎不报错也不走代理 |
| 原因 | Docker Desktop 读取时只认小写键名，写回时才规范化为 PascalCase |
| 影响 | 排障来回重启引擎 4 次 |
| 解决 | 统一写小写键；并用 `docker info` 的错误信息确认「via app settings HTTPS proxy」 |
| 验证 | 同上一条 |
| 状态 | 已解决并写入部署说明 |

## 三、`proxyHttpMode: "none"` 导致引擎无法启动

| 项 | 内容 |
| --- | --- |
| 现象 | 写入 `"none"` 后 `docker-desktop` WSL 发行版一直是 Stopped |
| 原因 | 该值不是合法枚举 |
| 影响 | 容器与 PowerSystem 服务全部停机约 6 分钟 |
| 解决 | 还原配置并改用 `manual` + 局域网 IP |
| 验证 | 引擎恢复正常，容器自动回来 |
| 状态 | 已解决；写入「不要使用 none」的约束 |

## 四、PowerShell 脚本中文输出乱码

| 项 | 内容 |
| --- | --- |
| 现象 | `sync.ps1` 输出的中文变成 `浠撳簱`，且 `$repoRoot` 未被替换 |
| 原因 | 脚本以 UTF-8 无 BOM 保存，Windows PowerShell 5.1 按 ANSI 解析，多字节序列吞掉了变量符号 |
| 影响 | 脚本仍能执行，但输出不可读，且有解析风险 |
| 解决 | 脚本内控制台输出改为 ASCII，注释保留中文 |
| 验证 | 重跑 `sync.ps1` 输出正常 |
| 状态 | 已解决；写入 `deploy/README.md` 的脚本约定 |

## 五、FastAPI 通配路由吃掉具体路径

| 项 | 内容 |
| --- | --- |
| 现象 | `POST /sim/scenario/normal` 被 `/sim/scenario/{key}` 匹配 |
| 原因 | FastAPI 按声明顺序匹配 |
| 影响 | 「恢复正常」会走剧本触发分支，不清除强制行为 |
| 解决 | 把具体路径声明移到通配路径之前 |
| 验证 | 恢复接口返回 `{"scenario":"normal"}` 且目标行为复原 |
| 状态 | 已解决 |

## 六、置信度阈值过滤掉一半目标

| 项 | 内容 |
| --- | --- |
| 现象 | 模拟世界 8 个游客，快照只回 5 个目标 |
| 原因 | `MockDetector` 置信度区间 0.58–0.96，低于高峰档阈值 0.70 的被过滤 |
| 影响 | 演示时人数与画面不一致，看起来像漏检 |
| 解决 | 占位置信度改为 0.72–0.97，使高峰档保留全部目标，低谷档（0.85）仍有可观察的过滤效果 |
| 验证 | 冒烟脚本 `targets=8` |
| 状态 | 已解决 |

## 七、静止时长依赖手环，无手环目标永远到不了强告警

| 项 | 内容 |
| --- | --- |
| 现象 | 剧本目标 7 号（无手环）最高只到 WEAK 0.55，长时间不下沉也升不到 STRONG |
| 原因 | 打分器的「静止」分项只读手环 `stillSec`，无手环即为 0，分数上限被锁死在 0.55 |
| 影响 | 演示主线（静止下沉 → 强告警）走不通 |
| 解决 | 改为**用检测框中心位移判断静止**（指数平滑后求速度，阈值 0.004/s），手环静止时长只做取大值补充 |
| 验证 | 40 秒后目标 7 = STRONG 0.85，`stillSec=30.7`，`speed=0.0011` |
| 状态 | 已解决 |

## 八、站立/踩水被误累积成静止

| 项 | 内容 |
| --- | --- |
| 现象 | 浅水区站立的目标稳定停在 NOTICE 0.4，看板一直有「风险目标」 |
| 原因 | 站立时手环 `stillSec` 持续增长，直接计入静止分项 |
| 影响 | 演示时噪声大，真正的告警不突出 |
| 解决 | 静止只在水下静止/漂浮姿态下累积，站立与踩水按衰减处理 |
| 验证 | 复跑后非剧本目标回到 NORMAL 0.1 |
| 状态 | 已解决 |

## 九、剧本结束后目标仍保持水下姿态

| 项 | 内容 |
| --- | --- |
| 现象 | 剧本超时后，目标姿态仍是 `underwater_still`，风险分缓慢回升 |
| 原因 | 只清空了 `forced` 标记，没有复位 `posture` |
| 影响 | 演示切换剧本时状态不干净 |
| 解决 | 剧本到期与手动恢复正常时，统一复位姿态为 `swimming` 并清零静止累计 |
| 验证 | 恢复正常剧本后目标回到游泳姿态，风险分衰减 |
| 状态 | 已解决 |

## 十、远端与本机时区不同

| 项 | 内容 |
| --- | --- |
| 现象 | 远端日期比本机晚一天，日志时间「对不上」 |
| 原因 | 本机为 UTC-8，远端与容器为 `Asia/Shanghai` |
| 影响 | 容易被误判为时钟错误 |
| 解决 | 不改时钟；明确「时间戳以服务端（+08:00）为准」，容器统一 `TZ=Asia/Shanghai` |
| 验证 | 接口 `time` 字段为 `+08:00` |
| 状态 | 已确认，无需修复 |
