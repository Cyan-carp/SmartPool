# S04 · 问题记录与解决方案

## 一、`GET /zones` 映射冲突

| 项 | 内容 |
| --- | --- |
| 现象 | 启动报 `Ambiguous mapping`，`/api/v1/zones` 同时被两个控制器注册 |
| 原因 | 新增 `ZoneController` 时没有把 `PoolController` 里的只读区域接口摘掉 |
| 影响 | 后端无法启动 |
| 解决 | 删除 `PoolController` 中的 zones 方法，区域统一归 `ZoneController` |
| 验证 | 服务正常启动，区域接口返回 4 条 |
| 状态 | 已解决 |

## 二、池边目标「未分区」

| 项 | 内容 |
| --- | --- |
| 现象 | M3 告警详情区域为空 |
| 原因 | 三块围栏没有覆盖池边，点在多边形外 |
| 影响 | 演示少一个信息、统计无法归区 |
| 解决 | 新增 `V4__pool_zone.sql` 插入 `POOL` 类型「全池」；`POOL` 不可删除（409） |
| 验证 | 区域列表 4 条，越界告警区域名正确 |
| 状态 | 已解决（M3 遗留关闭） |

## 三、解绑手环没有生效

| 项 | 内容 |
| --- | --- |
| 现象 | 调 `/wristbands/{code}/unbind` 返回 200，但列表里绑定关系还在（bound 从 2 变 3 且回不去） |
| 原因 | MyBatis-Plus 的 `updateById` 默认忽略 null 字段，`setBindTrackNo(null)` 不会写库 |
| 影响 | 手环与目标无法解绑，演示时绑定关系错乱 |
| 解决 | 改用 `lambdaUpdate().set(Wristband::getBindTrackNo, null)` 显式置空 |
| 验证 | 解绑后返回 `bindTrackNo=None`，bound 回到 2 |
| 状态 | 已解决（同类问题在其它字段上也要注意） |

## 四、越界告警每分钟重复建单

| 项 | 内容 |
| --- | --- |
| 现象 | 儿童持续待在深水区时，同一目标每分钟产生一条新告警 |
| 原因 | 只依赖 60 秒去重桶，没有「本次越界已上报」的状态 |
| 影响 | 告警列表噪声大，掩盖真实事件 |
| 解决 | `BoundaryGuard` 增加 `alerted` 标记：同一次进入只报一次，离开区域后重置 |
| 验证 | 同一目标持续越界期间不再新增告警；离开再进入会重新触发 |
| 状态 | 已解决 |

## 五、前端缺 echarts 依赖

| 项 | 内容 |
| --- | --- |
| 现象 | 看板页白屏，控制台报 `Failed to resolve import "echarts"` |
| 原因 | 看板改造引入了 echarts，但 `package.json` 还是 M1 的最小集合 |
| 影响 | 三张图无法渲染 |
| 解决 | 加入 `echarts ^5.5.1`，镜像内走 `registry.npmmirror.com` 安装 |
| 验证 | 镜像构建通过，页面 200，图表区块正常 |
| 状态 | 已解决 |

## 六、验收脚本绑定到已占用的目标

| 项 | 内容 |
| --- | --- |
| 现象 | 脚本第 7 步返回 409 |
| 原因 | 写死了 `trackNo=8`，上一轮已绑过 |
| 影响 | 误报失败 |
| 解决 | 改为取「当前已绑定的最大目标号 + 1」 |
| 验证 | 脚本一次通过 |
| 状态 | 已解决 |
