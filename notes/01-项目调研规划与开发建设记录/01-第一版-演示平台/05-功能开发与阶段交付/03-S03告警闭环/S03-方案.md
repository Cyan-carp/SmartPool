# S03 · 告警闭环 · 方案

> M3 开工方案。执行结果见 [[S03-测试与交付]]。

## 一、范围

| 类别 | 内容 |
| --- | --- |
| 入库 | 风险事件落库；同泳池 + 同目标 + 同区域 60 秒窗口去重 |
| 状态机 | `OPEN → ACKED → DISPATCHED → RESOLVED`，旁路 `FALSE_ALARM`；非法流转返回 40900 |
| 升级 | 未处置的弱告警 30 秒后自动升为强告警，并记一条 `ESCALATE` |
| 处置 | 确认 / 派单 / 解除 / 误报，全部写 `alert_action` 与 `audit_log` |
| 回溯 | 每秒一条轨迹采样，告警前后各 20 秒窗口 |
| 实时 | WS `alert.created` / `alert.updated` 推送到告警中心 |
| 统计 | 近 24 小时：总数、待确认、已解除、误报率、平均响应 |
| 导出 | `GET /alerts/export.csv`，带 BOM 便于 Excel 打开 |
| 演示控制 | 后端 `/demo/*` 转发剧本与重置（顺带补上 M6 的控制台能力） |

## 二、不做的

- 告警通知外发（Webhook/飞书）仍为 P1。
- 事件片段不做视频截图，只存轨迹与风险分。
- 统计不做历史趋势图（M4 用 ECharts）。

## 三、关键口径

| 项 | 取值 |
| --- | --- |
| 建单门槛 | 目标等级 ≥ WEAK（NOTICE 不建单，避免噪声） |
| 去重窗口 | 60 秒（`dedup_key = pool:track:zone:bucket`） |
| 升级阈值 | 未处置 30 秒，WEAK → STRONG |
| 首次响应 | `firstAckAt - triggeredAt` |
| 误报率 | `FALSE_ALARM / (RESOLVED + FALSE_ALARM)` |
| 轨迹保留 | 30 分钟，定期清理 |

## 四、验收口径

1. 触发「静止下沉」后能产生告警，等级与风险分一致。
2. 确认 → 派单 → 解除全链路可用，重复确认被 409 拦住。
3. 详情返回处置时间线与 ≥10 个轨迹采样点。
4. 统计数字随处置实时变化。
5. CSV 可下载且表头正确。
