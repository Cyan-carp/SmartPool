# S03 · 问题记录与解决方案

## 一、触发剧本从宿主机调不通

| 项 | 内容 |
| --- | --- |
| 现象 | `curl 127.0.0.1:8010/sim/scenario/drown_still` 返回空，剧本始终是 normal |
| 原因 | 模拟源容器没有发布端口（只有 nginx 映射到宿主机），宿主机根本连不上 8010 |
| 影响 | 以为剧本生效，实际什么都没发生，白等 45 秒 |
| 解决 | 新增后端 `/api/v1/demo/*` 转发接口（剧本、时钟、重置），宿主机只经 nginx 访问 |
| 验证 | `python deploy/scripts/trigger.py drown_still` 返回 `{"scenario":"drown_still","target":7}` |
| 状态 | 已解决，同时补齐 M6 演示控制台的后端能力 |

## 二、后端缺 `SIMULATOR_URL`，演示接口返回 503

| 项 | 内容 |
| --- | --- |
| 现象 | `/demo/scenarios/drown_still` 返回 503 |
| 原因 | compose 的 backend 环境变量只配了 `AI_URL`，模拟源地址退回 `localhost:8010`（容器内不存在） |
| 影响 | 演示控制不可用 |
| 解决 | compose 增加 `SIMULATOR_URL: http://simulator:8010`，并把推送间隔也显式化 |
| 验证 | 触发接口返回 200，告警正常产生 |
| 状态 | 已解决 |

## 三、验收脚本把 token 传成了 body

| 项 | 内容 |
| --- | --- |
| 现象 | 详情与统计接口返回 401，但列表接口正常 |
| 原因 | `call()` 签名是 `(method, path, body, token)`，两处 GET 用位置参数把 token 传给了 body |
| 影响 | 脚本误报失败，实际接口正常 |
| 解决 | 改为关键字参数 `token=token` |
| 验证 | 脚本一次通过，9 项全绿 |
| 状态 | 已解决（脚本自身缺陷，不影响产品） |

## 四、告警一创建就是 STRONG

| 项 | 内容 |
| --- | --- |
| 现象 | 第一条告警直接是强告警，没看到「弱→强」的升级过程 |
| 原因 | 建单在风险分越过 0.80 之后才发生，等级按当时分值取；升级逻辑只对「先建单后升级」的场景生效 |
| 影响 | 演示时看不到自动升级链路 |
| 解决 | 不改代码：演示时开启 5× 时钟或提前触发，让告警先在 WEAK 建单；升级定时任务每 5 秒扫一次 |
| 验证 | 第二条告警以 WEAK 建单，处置前保持 WEAK，统计中可见强弱分布 |
| 状态 | 已确认（行为符合设计，记录为演示注意事项） |

## 五、区域显示「未分区」

| 项 | 内容 |
| --- | --- |
| 现象 | 告警详情的区域字段为空 |
| 原因 | 目标位置落在三块围栏多边形之外（池边区域），`ZoneLocator` 返回 null |
| 影响 | 演示时少一个信息点 |
| 解决 | 短期按「未分区」展示；M4 增加覆盖整池的默认区域，围栏绘制时一并处理 |
| 验证 | 当前展示为「未分区」，不报错 |
| 状态 | 遗留至 M4 |
