# S05 · 问题记录与解决方案

## 一、设备两张表主键冲突

| 项 | 内容 |
| --- | --- |
| 现象 | 摄像头与传感器分属 `camera` / `device` 两张表，`/devices` 返回的 id 会重复 |
| 原因 | 两张表各自自增，不能直接当统一主键 |
| 影响 | 前端维护操作可能打到错误设备 |
| 解决 | 统一标识用 `camera-1` / `device-2`，后端解析前缀路由到对应表 |
| 验证 | 维护接口对 `camera-1` 生效，传感器不受影响 |
| 状态 | 已解决 |

## 二、水质最新值取不到

| 项 | 内容 |
| --- | --- |
| 现象 | 停服重启后 `/water-quality/latest` 返回空对象 |
| 原因 | 直接读实时帧，而首帧要等推理服务起来 |
| 影响 | 页面首次加载空白 |
| 解决 | 优先取实时帧，取不到回落到数据库最近一条，并标记 `source=history` |
| 验证 | 重启后首次请求有值 |
| 状态 | 已解决 |

## 三、维护记录写入但指标不变

| 项 | 内容 |
| --- | --- |
| 现象 | 清洁维护后清洁度仍是 0.95 |
| 原因 | 只在 `maintenance_log` 落库，没有回写摄像头指标 |
| 影响 | 演示看不出维护效果 |
| 解决 | 按维护类型回写：`CLEAN`→清洁度 0.99、`SEAL_CHECK`→密封 0.99、`REBOOT`→在线 |
| 验证 | 验收脚本显示 0.95 → 0.99 |
| 状态 | 已解决 |

## 四、切档后推理服务没变

| 项 | 内容 |
| --- | --- |
| 现象 | 后端档位切了，但推理服务的阈值仍是 0.70 |
| 原因 | 只写了数据库/缓存，没有调用推理服务 `/mode` |
| 影响 | 演示「切档」只有界面变化，判定行为不变 |
| 解决 | `ModelService.setMode` 里调用 `AiClient.setMode`，失败返回 50300；同时存 Redis 供查询 |
| 验证 | 切到 OFFPEAK 后推理 `/mode` 返回 0.85 / 60s / 2×2 |
| 状态 | 已解决 |

## 五、指标曲线一开始是空的

| 项 | 内容 |
| --- | --- |
| 现象 | 首次打开模型页，曲线无数据 |
| 原因 | 指标采样 10 秒一次，刚启动还没有点 |
| 影响 | 观感差 |
| 解决 | 验收脚本与页面都做「等待一次采样」处理；页面 10 秒轮询自动补 |
| 验证 | 等待 12 秒后 4 个采样点 |
| 状态 | 已解决（体验问题，非缺陷） |
