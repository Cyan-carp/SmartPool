# S02 · 问题记录与解决方案

> M2 实际遇到的问题与处置。

## 一、推送频率与缓存写入耦合

| 项 | 内容 |
| --- | --- |
| 现象 | 把推送从 1 Hz 提到 10 Hz 后，Redis 每秒被写 10 次 |
| 原因 | 取帧、写缓存、广播写在同一个定时任务里，没有区分频率 |
| 影响 | 无谓的 Redis 压力；后续多实例时放大 |
| 解决 | 拆分：广播跟随 `push-interval-ms`（100 ms），Redis 写入由 `redis-cache-ms`（1000 ms）节流 |
| 验证 | 10 Hz 推送下 `check_ws.py` 速率稳定，Redis 写入量下降 90% |
| 状态 | 已解决 |

## 二、降级提示依赖普通变量，界面不刷新

| 项 | 内容 |
| --- | --- |
| 现象 | 自查时发现 `noticeDegraded` 用 `let` 声明，模板与 `computed` 读不到变化 |
| 原因 | Vue 的响应式只跟踪 `ref`/`reactive` |
| 影响 | 推理挂掉后横幅可能不出现 |
| 解决 | 改为 `ref(false)`，所有赋值改 `.value` |
| 验证 | 降级/恢复脚本与页面状态一致（`dataDelayMs` 8 s → 61 ms） |
| 状态 | 已解决（构建前自查发现） |

## 三、降级判定过慢或过早都影响演示

| 项 | 内容 |
| --- | --- |
| 现象 | 最初每次推理失败就广播通知，网络抖动时刷屏 |
| 原因 | 没有防抖与状态记忆 |
| 影响 | 前端横幅闪烁 |
| 解决 | 只在「连续静默 > 3 s 且当前为正常态」时广播一次降级；恢复时广播一次 `ok`，并用 `degraded` 标志位防重复 |
| 验证 | 停 7 s 触发一次降级，恢复后一次恢复通知 |
| 状态 | 已解决 |

## 四、10 Hz 推送看起来卡顿

| 项 | 内容 |
| --- | --- |
| 现象 | 直接按推送帧重绘，目标位置一跳一跳 |
| 原因 | 渲染频率与推送频率绑定 |
| 影响 | 大屏观感差，像低帧率视频 |
| 解决 | 位置按 `dt/140` 系数逼近目标值，渲染保持 60 FPS；底图放离屏 Canvas 只画一次 |
| 验证 | 代码层面帧循环与推送解耦；实际 FPS 待浏览器确认 |
| 状态 | 已解决（视觉待人工确认） |

## 五、目标消失后残留

| 项 | 内容 |
| --- | --- |
| 现象 | 目标离场后框仍停在原位 |
| 原因 | 渲染表只增不删 |
| 影响 | 画面出现「幽灵目标」 |
| 解决 | 3 秒未收到该 `trackNo` 即从渲染表移除 |
| 验证 | 剧本切换后画面干净 |
| 状态 | 已解决 |

## 六、悬停卡片与右侧列表联动

| 项 | 内容 |
| --- | --- |
| 现象 | 鼠标离开画布后卡片消失，但右侧列表高亮还在 |
| 原因 | 两个状态没有统一 |
| 影响 | 视觉不一致 |
| 解决 | 列表悬停时用 `pinnedTrack` 驱动卡片内容，画布离开只清空 `hovered` 不清 `pinnedTrack` |
| 验证 | 交互自查通过 |
| 状态 | 已解决 |
