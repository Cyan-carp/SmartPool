# S02 · 实时监控 · 方案

> M2 开工方案。执行结果见 [[S02-测试与交付]]。

## 一、范围

| 类别 | 内容 |
| --- | --- |
| 推送链路 | 帧推送频率与 Redis 缓存频率解耦；默认 10 Hz 推送、1 s 缓存 |
| 降级处理 | 推理不可用时冻结画面并广播一次降级通知；恢复时补发恢复通知 |
| 渲染分层 | 离屏底图（池体/泳道/区域）+ 精灵层 + 检测框叠加层，只重绘变化部分 |
| 插值 | 目标位置按帧间线性逼近，避免 10 Hz 推送看起来卡顿 |
| 交互 | 悬停目标弹出信息卡（姿态、风险分、头部未出水、静止、手环、置信度） |
| 状态可见 | 顶部降级横幅、底部状态条（FPS、帧序号、推理耗时、延迟、在线端、档位、剧本） |
| 重连 | WS 指数退避重连，重连成功后拉 `/live/snapshot` 对齐 |

## 二、不做的

- 不做真实视频解码与 FFmpeg 转码（演示画面为 Canvas 合成）。
- 不做目标轨迹的历史回放（M3）。
- 不做多路摄像头切换（M4 之后按需）。

## 三、验收口径

1. 推送速率 ≥ 5 Hz（目标 10 Hz）。
2. 浏览器渲染 ≥ 25 FPS（需人工确认）。
3. 停止推理服务后 3–10 秒内进入降级状态，页面横幅提示；恢复后自动回到正常。
4. 断线重连后画面与计数自动对齐，无重复目标。
5. 悬停任意目标能看到该目标的判定依据。

## 四、契约变化

- `frames` 增加 `params`（当前档位阈值、滑窗、步长、算力占比）。
- `/live/snapshot` 增加 `degraded`、`pushedFrames`、`failedFrames`。
- 新增 WS 通知语义：`system.notice.level` ∈ `info` / `degraded` / `ok`。

> 以上均为**只增不改**，符合 [[01-项目调研规划与开发建设记录/01-第一版-演示平台/03-架构设计/02-接口契约]] 第五节兼容规则。
