# 数据模型

> 演示版 MySQL 8.0 结构。约定：表名 `snake_case` 单数、主键 `id BIGINT AUTO_INCREMENT`、统一含 `created_at` / `updated_at`、软删用 `deleted_at`（时间戳，NULL 为未删）。

## 一、表清单

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `sys_user` | 账号与角色 | `username` 唯一；密码 BCrypt |
| `pool` | 泳池 | `name`、`length_m`、`width_m`、营业时段 |
| `camera` | 摄像头 | `pool_id`、`position`、`status` |
| `zone` | 区域与电子围栏 | `pool_id`、`type`、`polygon_json`、`allowed_groups` |
| `wristband` | 智能手环（合成） | `code` 唯一、`bind_track_id`（可空） |
| `track` | 目标轨迹（按会话） | `pool_id`、`track_no`、`started_at`、`ended_at` |
| `track_point` | 轨迹采样点 | `track_id`、`ts`、`x`、`y`、`posture`、`risk_score` |
| `risk_event` | 风险事件（判定结果） | `pool_id`、`track_id`、`risk_score`、`reason`、`evidence_json` |
| `alert` | 告警（生命周期） | `risk_event_id`、`level`、`status`、`dedup_key` 唯一 |
| `alert_action` | 处置时间线 | `alert_id`、`action`、`operator_id`、`note` |
| `event_clip` | 事件片段（回溯素材） | `risk_event_id`、`window_start`、`window_end` |
| `device` | 设备（含网关、传感器） | `pool_id`、`type`、`status`、`metrics_json` |
| `maintenance_log` | 设备维护记录 | `device_id`、`type`、`operator_id` |
| `water_quality` | 水质采样 | `pool_id`、`ts`、`temperature`、`turbidity`、`ph`、`chlorine` |
| `model_param` | 算力档位参数模板 | `mode` 唯一；阈值、T、步长 |
| `model_metric` | 推理指标采样 | `ts`、`latency_ms`、`fps`、`compute_ratio` |
| `export_job` | 导出任务 | `status`、`file_path`、`requested_by` |
| `audit_log` | 审计 | `actor_id`、`action`、`target_type`、`target_id`、`detail_json` |
| `demo_scenario_run` | 剧本执行记录 | `scenario_key`、`run_id`、`started_at`、`result` |

## 二、关键字段与枚举

### `zone.type`

`DEEP` / `SHALLOW` / `KIDS` / `LANE` / `RESTRICTED`

### `zone.polygon_json`

归一化多边形点数组，前端与后端共用同一坐标系：

```json
{ "points": [{"x":0.12,"y":0.20},{"x":0.48,"y":0.19},{"x":0.50,"y":0.62},{"x":0.10,"y":0.63}],
  "version": 1 }
```

### `alert`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `level` | enum | `NOTICE` / `WEAK` / `STRONG` |
| `status` | enum | `OPEN` / `ACKED` / `DISPATCHED` / `RESOLVED` / `FALSE_ALARM` |
| `dedup_key` | varchar(96) | `poolId:trackId:zoneId:levelBucket`，防重复 |
| `triggered_at` | datetime(3) | 服务端时钟 |
| `first_ack_at` | datetime(3) | 首次确认时间，用于响应时长统计 |
| `closed_at` | datetime(3) | 关闭时间 |
| `reason` | varchar(255) | 人类可读触发原因（规则 + 分数） |

### `risk_event.evidence_json`

```json
{
  "headUnderwaterSec": 32,
  "stillnessSec": 28,
  "riskScore": 0.86,
  "windowT": 30,
  "wristband": {"heartRate": 128, "spo2": 96, "still": true},
  "provider": "mock",
  "placeholder": true
}
```

> `placeholder: true` 必须在所有对外展示处可见（详情页、导出文件），防止把演示结果当真实模型输出。

## 三、索引与容量

| 表 | 索引 |
| --- | --- |
| `alert` | `(pool_id, status, triggered_at)`、`dedup_key` 唯一 |
| `risk_event` | `(pool_id, triggered_at)`、`(track_id)` |
| `track_point` | `(track_id, ts)`；演示保留 7 天，定时清理 |
| `water_quality` | `(pool_id, ts)` |
| `model_metric` | `(ts)` |
| `audit_log` | `(actor_id, created_at)` |

- 单泳池 QC 目标上限 200，采样 5 点/秒 → 约 1000 行/秒；演示保留 7 天，`track_point` 用批量插入 + 分区表（按月）预留。
- 清理任务：每日 03:00 删除 7 天前的 `track_point`、`model_metric`；`alert` 与 `audit_log` 不自动删。
