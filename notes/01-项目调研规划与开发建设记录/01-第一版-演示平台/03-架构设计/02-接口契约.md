# 接口契约

> 本页是前后端与推理服务之间的**唯一契约来源**。字段名、枚举值、错误码改动必须先改本页；三端不一致视为该功能未完成。

## 一、通用约定

| 项 | 约定 |
| --- | --- |
| 基础路径 | `/api/v1`（前端经 Vite 代理 / Nginx 转发到 `:8080`） |
| 鉴权 | `Authorization: Bearer <jwt>`；`/auth/login` 除外 |
| 时间 | ISO-8601 带时区，如 `2026-11-05T14:03:21+08:00`；服务端时钟为准 |
| 坐标 | 归一化 `0..1`，原点左上；框为 `{x,y,w,h}` |
| 分页 | `?page=1&size=20` → `{list,total,page,size}` |
| 幂等 | 写操作支持 `Idempotency-Key` 头（告警处置、剧本注入必填） |

### 响应包络

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "b7f1c2d3e4a5"
}
```

### 错误码

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 0 | 成功 | — |
| 40001 | 参数校验失败 | 表单就地提示 `message` |
| 40100 | 未登录 / token 过期 | 清空登录态，跳登录 |
| 40300 | 角色无权 | 提示无权限，不跳转 |
| 40400 | 资源不存在 | 列表刷新 |
| 40900 | 状态冲突（如重复处置） | 刷新详情后重试 |
| 42900 | 触发限流 | 退避重试 |
| 50000 | 服务内部错误 | 通用错误提示 + traceId |
| 50300 | 依赖不可用（推理/DB） | 顶部横幅「服务降级」 |

## 二、REST 接口

### 2.1 认证与用户

| 方法 | 路径 | 角色 | 说明 |

### 2.2 泳池、摄像头与区域

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/pools` | 全部 | 泳池列表（含分区数与在线摄像头数） |
| GET | `/pools/{id}` | 全部 | 泳池详情（规格、深浅水比例、营业时段） |
| GET | `/cameras?poolId=` | 全部 | 摄像头列表及健康状态 |
| GET | `/zones?poolId=` | 全部 | 区域与围栏多边形（归一化点集） |
| POST | `/zones` | 管理员 | 新建区域 `{poolId,name,type,allowedGroups,polygon[]}` |
| PUT | `/zones/{id}` | 管理员 | 更新区域/多边形 |
| DELETE | `/zones/{id}` | 管理员 | 删除（有活动告警时返回 40900） |
| PUT | `/zones/{id}/exemptions` | 管理员 | 豁免对象规则（如工作服颜色标签） |

`type` 枚举：`DEEP`（深水区）、`SHALLOW`（浅水区）、`KIDS`（儿童区）、`LANE`（泳道）、`RESTRICTED`（禁入）、`POOL`（全池兜底，唯一且不可删除）

> `POOL` 为 M4 新增：保证任何目标都有归属，细节区域优先命中；删除接口对其返回 40900。

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/live/snapshot?poolId=` | 全部 | 当前帧快照（WebSocket 重连后补拉）：目标列表、计数、模式、时间戳 |
| GET | `/live/tracks?poolId=&from=&to=` | 全部 | 轨迹查询（回溯用） |

`range` 枚举：`1h`、`6h`、`24h`、`7d`

### 2.4 告警与事件

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/alerts?status=&level=&poolId=&from=&to=&page=` | 全部 | 告警列表（默认 24h 内、未关闭优先） |
| GET | `/alerts/active?poolId=` | 全部 | **大屏锁存源**：未确认（`OPEN`）告警，含 `active` 标记（目标当前是否仍在报警） |
| GET | `/alerts/{id}` | 全部 | 详情：触发依据、轨迹片段、手环数据、处置时间线 |
| POST | `/alerts/{id}/ack` | 救生员/管理员 | 确认：`{note}` |
| POST | `/alerts/{id}/dispatch` | 救生员/管理员 | 派单：`{assigneeId,note}` |
| POST | `/alerts/{id}/resolve` | 救生员/管理员 | 解除：`{result, note}`，`result` ∈ `RESCUED`/`SELF_RECOVERED`/`FALSE_ALARM` |
| POST | `/alerts/{id}/escalate` | 系统 | 超时升级（内部/定时任务） |
| GET | `/events/{id}/clip` | 全部 | 事件片段：时间窗内轨迹、风险曲线、截图引用 |
| POST | `/events/export` | 管理员 | 异步导出任务 `{alertIds[],format}` → `{jobId}` |
| GET | `/events/export/{jobId}` | 管理员 | 导出状态与下载路径 |

`status` 枚举：`OPEN`、`ACKED`、`DISPATCHED`、`RESOLVED`、`FALSE_ALARM`
`level` 枚举：`NOTICE`、`WEAK`、`STRONG`

### 锁存语义（M6 之后确立）

- **同池 + 同目标 + 同区域**只允许存在一条 `OPEN` 告警；风险继续升级时只更新该条（升级记 `ESCALATE`），不再新开单。
- 目标恢复正常不会自动关闭告警，状态保持 `OPEN`，大屏显示「已恢复 · 待确认」。
- 只有人工 `ack / resolve / false-alarm` 才关闭；随后同一目标再次超阈值才会产生新告警。
- 大屏的待确认列表必须来自 `GET /alerts/active`，**禁止用浏览器 `localStorage` 充当事实源**（换设备会丢、无审计、无法追责）。

## 三、WebSocket 契约

- 地址：`/ws/live`，握手参数 `?token=<jwt>&poolId=<id>`
- 心跳：服务端每 15s 发 `ping`，客户端 20s 内未收到则主动重连
- 重连：指数退避 1s/2s/5s/10s，最多 10 次；重连成功后先拉 `/live/snapshot`

### 消息包络

```json
{ "type": "frames", "ts": "2026-11-05T14:03:21.120+08:00", "seq": 10321, "payload": {} }
```

### 消息类型

| type | 方向 | payload 关键字段 |
| --- | --- | --- |
| `frames` | 服务端 → 前端 | `poolId`、`targets[]`（`trackId`、`box`、`posture`、`riskScore`、`zoneId`、`wristbandId`）、`counts` |
| `alert.created` | 服务端 → 前端 | `alert`（id、level、poolId、trackId、zoneId、triggeredAt、reason） |
| `alert.updated` | 服务端 → 前端 | `alertId`、`status`、`operator`、`at` |
| `device.status` | 服务端 → 前端 | `deviceId`、`online`、`metrics`、`at` |
| `water.quality` | 服务端 → 前端 | `poolId`、`temperature`、`turbidity`、`ph`、`chlorine`、`exceeded[]` |
| `model.mode` | 服务端 → 前端 | `mode`、`params`、`changedBy` |
| `system.notice` | 服务端 → 前端 | `level`、`message`（推理中断、降级等） |
| `demo.clock` | 服务端 → 前端 | `speed`、`simTime` |
| `pong` | 双向 | `ts` |

`posture` 枚举：`swimming`、`floating`、`standing`、`treading`、`underwater_still`、`diving`、`unknown`

## 四、推理服务内部契约（不外网暴露）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/infer` | 入参 `{poolId,cameraId,ts,frames:[{seq,imageRef?}],mode}`；出参 `{targets[],inferMs,provider}` |
| POST | `/internal/risk-events` | 后端接收的风险事件（后端为服务端，推理侧调用） |
| POST | `/mode` | 切换档位与参数，后端调用 |
| POST | `/demo/scenario` | 剧本注入，转发到剧本引擎 |
| POST | `/reset` | 重置跟踪器与风险窗口 |
| GET | `/health` | `{ok,provider,modelLoaded,version}` |

> `modelLoaded=false` 是演示版的**正常状态**，不是故障。前端「模型面板」必须显式标注「占位模式」。
