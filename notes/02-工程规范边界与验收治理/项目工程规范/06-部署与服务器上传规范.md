# 06 · 部署与服务器上传规范

> 本机编排与演示机部署的规则。具体命令只在 `deploy/README.md` 与各阶段 README 维护，本卷不复制命令。

## 一、端口与进程

| 服务 | 端口 | 对外暴露 |
| --- | --- | --- |
| Nginx（统一入口） | 80 / 443 | 是 |
| 前端静态资源 | 由 Nginx 托管 | 经 Nginx |
| 后端 API + WebSocket | 8080 | 仅内网（Nginx 反代） |
| 推理服务 | 8000 | 否（仅后端可达） |
| 模拟数据源 | 8010 | 否（仅推理/后端可达） |
| MySQL | 3306 | 否 |
| Redis | 6379 | 否 |

> 推理服务、模拟数据源、数据库**一律不暴露公网**。演示机只开放 80/443。

## 二、编排约定

- `deploy/compose.yaml` 是唯一编排入口；服务名固定为 `nginx`、`backend`、`ai`、`simulator`、`mysql`、`redis`。
- 数据卷命名 `smartpool-<服务>-data`；严禁在发布流程中使用 `down -v`。
- 环境变量来自根 `.env`（不入 Git），模板为 `.env.example`。
- 服务间依赖用 `depends_on: condition: service_healthy`，每个服务必须提供健康检查。
- 日志统一输出到 stdout，由 Docker 轮转（`max-size=50m`、`max-file=3`）。

## 三、演示机部署检查表

上传或部署前逐项核对，任一项不通过则不上：

- **目标确认**：部署到哪台机器、哪个目录、由谁操作，写清并当场核对。
- **版本确认**：部署的 commit 或 tag 明确，工作区无未提交改动（或已说明）。
- **配置确认**：`.env` 已按目标环境填好，`JWT_SECRET`、数据库口令不是默认值。
- **数据确认**：是否需要保留旧数据；重置则明确说明「本次会清空业务数据」。
- **回退方案**：保留上一版本镜像或源码快照，写明回退命令与验证点。
- **验收动作**：部署后做什么检查（登录、切剧本、看告警），由谁确认。

## 四、发布后验证

- 访问首页能登录，三角色菜单正确。
- 大屏有画面与目标，无 `placeholder` 缺失。
- 手动触发一条剧本，告警能出现并能处置。
- 查看后端与推理服务日志无异常堆栈。
- 记录部署批次到 [[04-部署发布与变更记录/部署与运维日志/00-索引·部署与运维日志]]。

## 五、安全底线

- 禁止把 `.env`、密钥、数据库导出文件、`artifacts/` 内的原始日志上传到公开仓库。
- 服务器上的私有配置放独立目录，权限最小化。
- 演示账号密码统一但不用于生产；对外演示前改为一次性口令。
- 不开放数据库公网端口；不使用 root 账号连接业务库。

## 六、备份与回退

- 演示环境采用「源码 + 数据卷快照」双备份；快照前先停写入。
- 回退顺序：回退镜像/代码 → 校验健康检查 → 验证登录与告警链路 → 记录批次。
- 数据库结构与代码不同版本时，先在隔离库验证迁移再上演示机。
