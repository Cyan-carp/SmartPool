# 05 · 演示数据与模型占位边界

> 演示版的两条底线：**数据全部合成、模型明确空置**。本卷规定怎么标记、怎么替换、什么不能对外说。

## 一、合成数据边界

| 项 | 规定 |
| --- | --- |
| 来源 | 全部由脚本生成；不采集真实泳池影像、不使用真实个人信息 |
| 可复现 | 固定随机种子；同种子重建结果一致 |
| 可识别 | 生成数据带 `synthetic: true` 标记（接口或库字段至少留一处） |
| 展示 | 演示页面底部标注「演示数据为合成数据」 |
| 外部数据 | 若引入公开数据集，先登记来源与许可证（见测试资产台账），不得静默混入 |

## 二、模型占位边界

- 推理服务对外只暴露 `Detector` 接口；`MockDetector` 与将来 `MambaYoloDetector` 签名一致。
- `GET /health` 必须如实返回 `modelLoaded: false`（占位时）。
- 所有由占位模型产生的数据带 `placeholder: true`，且在大屏、详情页、导出文件中可见。
- 「模型面板」页面必须显示「占位模式 · 未加载真实权重」。

## 三、替换真实模型的唯一路径

1. 在 `stages/03-ai-service` 新增 `MambaYoloDetector`，实现 `Detector` 的 `load()` 与 `infer()`。
2. 配置 `AI_DETECTOR_PROVIDER=mamba-yolo` 与 `AI_MODEL_PATH`。
3. 前端不改代码；若输出字段有新增，按 [[02-工程规范边界与验收治理/项目工程规范/03-接口契约与前后端联调规范]] 先改契约。
4. 在「问题记录」与状态页记录替换日期、权重来源与验证范围。

> 如果替换需要改前端协议或后端表结构，说明占位设计不合格，应先修抽象层再换模型。

## 四、阈值与参数口径

| 参数 | 演示值 | 归属 |
| --- | --- | --- |
| 头部未出水强告警阈值 | 30 s | 推理侧规则 |
| 静止判定 | 位移 < 0.01/帧 持续 20 s | 推理侧规则 |
| 风险分强告警 | ≥ 0.80 | 推理侧输出 → 后端判级 |
| 弱告警 | ≥ 0.55 | 同上 |
| 去重窗口 | 同目标同区域 60 s | 后端 |
| 升级 | WEAK 未处置 30 s → STRONG | 后端 |
| 浑浊度维护提示 | > 5 NTU | 后端水质 |

参数必须可配置，不写死在代码里。

## 五、禁止表述

> 以下说法在文档、答辩与演示中**禁止**使用：

- 「系统已实现溺水识别准确率 90%」——占位模型没有精度。
- 「延迟 ≤200 ms」「算力降低 30%」——未实测，最多写「申报书目标值」或「模拟值」。
- 「接入真实摄像头/手环」——演示版无硬件对接。
- 「已通过等保/隐私合规认证」——只做了加密传输与权限分级的设计约定。

正确表述示例：「演示版以占位模型跑通业务链路，真实模型接入后精度以实测报告为准。」
