# 08 · 文档同步与变更记录

> 目标：不要求每改一行就回写全部文档，但**改变口径的改动必须留痕**。

## 一、变更分档

| 档位 | 判定 | 必做的记录与验证 |
| --- | --- | --- |
| **日常本地** | 单文件修复、样式微调、文案、内部重构 | 一条变更记录；受影响功能自测 |
| **兼容普通发布** | 新增接口字段、新增页面、参数默认值调整 | 变更记录 + 更新契约/手册 + 一次联调 |
| **高风险变更** | 改枚举语义、改表结构、改鉴权、改告警判级、换模型提供者 | 变更记录 + 契约升级 + 迁移脚本隔离验证 + 全链路回归 + 回退方案 |

## 三、变更记录格式

写入 [[04-部署发布与变更记录/部署与运维日志/00-索引·部署与运维日志]]，每条含：

```text
编号：NN
日期：YYYY-MM-DD
档位：日常 / 兼容 / 高风险
范围：哪个阶段、哪些文件
原因：为什么要改
改动：关键点（不贴大段代码）
验证：怎么验的、结果如何、证据路径
回退：需要时怎么写
```

## 四、编号规则

- 文件名以两位编号开头（`NN-主题.md`），顺序追加，不复用、不因目录调整重排。
- 同一功能链上连续多批可合并为一页，页头写批次索引，正文按原批次分节，事实与日期不改写。
- 日常修复不新建阶段问题页，只写变更记录；阶段问题页只收阶段内的实现/测试问题。

## 五、不许做的事

- 用「下次一起补」跳过状态页更新。
- 用新记录覆盖旧失败批次。
- 在聊天里口头确认后不落文档。
- 改完代码不回写契约，导致文档与实现两套说法。
