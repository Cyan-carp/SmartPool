# 04 · 阶段验收判定与四件套

> 每个里程碑（M1–M6）收尾都必须交四件套并通过验收判定，否则不得标记完成、不得进入下一里程碑。

## 一、四件套

| 文件 | 何时写 | 必须包含 |
| --- | --- | --- |
| `01-方案.md` | 开工前 | 范围、契约引用、任务清单、验收口径、不做项 |
| `02-测试与交付.md` | 收尾 | 实际测试记录（命令、时间、`run_id`）、结果、证据位置、遗留项 |
| `03-问题记录与解决方案.md` | 全程 | 每条：现象、原因、影响、解决办法、验证结果、状态 |
| `04-阶段交接.md` | 收尾 | 怎么起、做到哪、已知坑、下一步、注意事项 |

## 二、验收必答五项

1. **做了什么**：对照阶段方案逐项列出，标记「已实现 / 已自测 / 已验收」三档，不得互相替代。
2. **遇到什么问题**：指向问题记录页，只留「问题 → 解决 → 验证」摘要。
3. **还有哪些没解决**：逐条注明归属里程碑与是否阻塞本阶段。
4. **能否进入下一阶段**：给出「可进入 / 不可进入」，不可进入时写明缺什么证据。
5. **口径是否一致**：与 [[01-项目调研规划与开发建设记录/01-第一版-演示平台/01-立项与需求/02-演示版需求与范围]] 的功能编号逐条对齐，无「文档有代码无」。

## 三、判定门槛（不满足不得签收）

- 「测试与交付」页已形成，结论与证据一一对应。
- 失败批次保留，不覆盖成通过记录。
- 问题记录中的阻塞项为 0。
- 演示路径能按 README 从零启动并走通本阶段功能。
- 笔记校验脚本通过。
- 契约文档与实际接口一致。

## 四、什么不算通过

> 以下情形不能作为验收依据：

- 只截图「页面能打开」，没有走通功能。
- 只有一次手工改库后的成功，没有从零重建。
- 「本地跑过」但 README 步骤复现不了。
- 用申报书的目标值（精度、延迟、算力降幅）充当本项目实测结果。
- 前端用 mock 数据演示，却记为后端接口已验收。

## 五、里程碑与证据对应

| 里程碑 | 必须留下的证据 |
| --- | --- |
| M1 | 登录成功截图、种子数据重建两次一致的记录 |
| M2 | 帧率截图（≥25 FPS）、断网重连前后的快照对比 |
| M3 | 一条完整告警从触发到关闭的时间线与回溯截图 |
| M4 | 围栏保存后刷新的坐标一致性、越界触发记录 |
| M5 | 切档前后参数与指标曲线对比截图 |
| M6 | 冷启动计时、完整演示录屏、重置后重复演示记录 |

证据统一存 `artifacts/<阶段>/<run_id>/`，笔记只引用路径。
