# 03 · 接口契约与前后端联调规范

> 契约唯一维护在 [[01-项目调研规划与开发建设记录/01-第一版-演示平台/03-架构设计/02-接口契约]]。本卷只规定**改契约的流程与联调纪律**。

## 一、改动顺序（固定）

```text
改契约文档 → 改后端 → 改前端 → 联调 → 补测试 → 记录变更
```

> 跳过第 1 步直接写代码，是返工的第一大来源。文档未改的接口变更，评审直接打回。

## 二、契约纪律

| 规则 | 说明 |
| --- | --- |
| 字段只增不改不删 | 改名或改语义必须升 `/api/v2` 或加新字段弃用旧字段 |
| 枚举容错 | 前端遇到未知枚举值降级为 `unknown`，不得白屏或抛错 |
| 错误码统一 | 只用契约表中的 code；新增错误码先登记再使用 |
| 时间与坐标 | 时间 ISO-8601 带时区；坐标归一化 0–1，不传像素 |
| 占位标记 | 来自占位模型的数据必须带 `placeholder: true` |
| 分页统一 | `page/size` 入参，`list/total/page/size` 出参 |

## 三、三端并行策略

- M1 完成后，后端与推理服务都可用**固定样例数据**响应，前端不必等真实逻辑。
- 前端在 `src/mocks/` 保留一份与契约同形的样例响应，仅在 `VITE_USE_MOCK=true` 时启用。
- 样例数据必须与契约同源：字段缺失或类型不符视为样例失效，需同步修正。

## 四、联调检查表

每次联调按序核对，全部通过才算联调完成：

- **鉴权**：未带 token 返回 40100；救生员调管理员接口返回 40300。
- **包络**：成功与失败都符合 `{code,message,data,traceId}`。
- **字段**：网络面板中的响应字段与契约逐条对照，无多余、无缺失。
- **枚举**：把枚举手工改成未知值，前端不崩。
- **时间**：跨时区/跨天场景显示正确（用服务端时间）。
- **空态**：列表为空、无告警、无数据时页面有明确空态文案。
- **异常**：停掉推理服务，前端出现降级提示且不白屏。
- **WS**：断开网络 10 秒，重连后数据对齐、无重复目标。

## 五、联调记录

- 每次联调在当阶段「测试与交付」页记一条：时间、范围、接口清单、发现的问题、结论。
- 问题一律进当阶段「问题记录与解决方案」页，不在聊天记录里口头解决。
