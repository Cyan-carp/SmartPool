# 08 · 告警锁存服务端化

## 一、基本信息

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-06（服务端 +08:00） |
| 档位 | **高风险变更**（告警建单规则变化 + 新增接口） |
| 目标机 | `home-dev` / `C:\home-dev\smartpool` |
| 变更镜像 | backend、nginx |
| 数据库 | 无迁移；`alert` 语义调整（同目标仅一条 `OPEN`） |

## 二、背景

大屏的「待确认风险」原来把锁存放在浏览器 `localStorage`：换浏览器即丢、无审计、与告警中心可能不一致。本次把锁存改到服务端。

## 三、改动

- 新增 `AlertBoardService` 与 `GET /api/v1/alerts/active?poolId=`：返回 `OPEN` 告警并标注 `active`（目标当前是否仍在报警）。
- `AlertService.ingest` 与 `createBoundaryAlert` 增加「已有 OPEN 同目标同区域则不新开单」的判断；风险升级只更新原单并记 `ESCALATE`。
- 大屏 `MonitorView` 删除 `HOLD_KEY` / `ACK_KEY` 本地锁存，改为 3 秒轮询 + WS `alert.created/updated` 刷新；「确认」按钮调用 `POST /alerts/{id}/ack`。
- 越界判定阈值：儿童进深水区 8 秒 → 15 秒（降低正常游泳时的误触发）。
- 新增验收脚本 `check_latch.py`。

## 四、验证

```text
[1] active(before) -> total=0
[2] active(after)  -> 1 条
    id=425 track=#7 level=WEAK active=True zone=浅水区 reason=头部未出水 25s；静止 1s
[3] server list    -> OPEN 告警 1 条（与 active 对应）
[4] active(acked)  -> total=0
[5] history        -> status=ACKED actions=2
结果：通过（告警锁存在服务端，确认后留痕）
```

## 五、回退

- 代码回退后大屏会退回本地锁存，历史数据不受影响。
- 数据：已存在的多条 `OPEN` 告警不会被自动合并；如需一次性清理，用演示控制台「一键重置（含清空告警）」。

## 六、边界

> 锁存的是「告警」而不是「每一帧风险」：`NOTICE`（提示级）不建单，只有 `WEAK` 及以上才进入待确认列表。确认后同一目标再次超阈值会重新建单，这是预期行为。
