# 运维与二次开发手册

> 面向开发者：怎么起、怎么排障、怎么加一个页面或接口、怎么换模型。

## 一、环境与命令

```powershell
# 引擎（远端重启机器后必须）
ssh home-dev schtasks /run /tn SmartPoolStartDocker
Start-Sleep 60

cd deploy\scripts
.\up.ps1                     # 同步 + 构建 + 启动
.\up.ps1 -SkipSync           # 只重建镜像
.\up.ps1 -NoBuild            # 只重启容器
.\tunnel.ps1                 # 本地 18080
.\logs.ps1 -Service backend  # 看日志（backend/ai/simulator/nginx/mysql/redis）
.\down.ps1                   # 停止（不删卷）
```

验收脚本：

```powershell
python deploy\scripts\smoke.py       # M1 冒烟
python deploy\scripts\check_ws.py    # 推送速率
python deploy\scripts\check_alerts.py
python deploy\scripts\check_m4.py
python deploy\scripts\check_m5.py
python deploy\scripts\check_m6.py
```

## 二、服务与端口

| 服务 | 容器 | 端口 | 对外 |
| --- | --- | --- | --- |
| Nginx + 前端静态 | smartpool-nginx | 80 → `127.0.0.1:18080` | 经隧道 |
| 后端 | smartpool-backend | 8080 | 否 |
| 推理 | smartpool-ai | 8000 | 否 |
| 模拟源 | smartpool-simulator | 8010 | 否 |
| MySQL | smartpool-mysql | 3306 | 否 |
| Redis | smartpool-redis | 6379 | 否 |

## 三、常见故障

| 现象 | 排查 | 处理 |
| --- | --- | --- |
| 页面打不开 | 隧道是否在跑 | 重开 `.\tunnel.ps1` |
| 大屏无画面/延迟增长 | `.\logs.ps1 -Service ai` | 看推理是否 503；重启 ai 容器 |
| 顶部「降级」横幅常亮 | `curl /api/v1/demo/status` | `aiOk=false` 时检查推理；`framesPaused=true` 时点「全部恢复」 |
| 告警不产生 | 剧本是否生效 | `trigger.py` 再触发一次，等 30–45 秒 |
| 手环解绑无效 | — | 已修：`updateById` 忽略 null，改用 `lambdaUpdate` |
| 图表空 | 采样时间不足 | 等 10–30 秒；停服过久会丢窗口 |
| 数据库连不上 | `.\logs.ps1 -Service mysql` | 等 healthcheck；必要时重建卷（会清数据） |

## 四、加一个接口（后端）

1. 在 `notes/…/03-架构设计/02-接口契约.md` 登记路径、入参、出参、错误码
2. `stages/02-backend/src/main/java/com/smartpool/<域>/` 下建 Controller / Service / Mapper
3. 需要新表时在 `src/main/resources/db/migration/` 加 `V6__xxx.sql`（只增不改）
4. 权限用 `@PreAuthorize`，写操作记 `AuditService`
5. 前端在 `src/api/index.ts` 与 `src/types/api.ts` 补类型
6. `.\up.ps1 -SkipSync` 重建并验证

## 五、加一个页面（前端）

1. `src/router/index.ts` 注册路由（带 `meta.title`）
2. `src/views/XxxView.vue` 新建页面
3. `src/layout/AppLayout.vue` 的 `MENU_DEFS` 加菜单项，并在 `UserView.menusOf` 里给角色授权
4. 需要图表时用 `echarts`，容器 `div` 给固定高度

## 六、换真实模型（唯一入口）

1. 在 `stages/03-ai-service/app/detector/` 新增 `mamba_yolo.py`，实现 `Detector` 的 `load()` / `infer()` / `model_loaded`
2. 修改 `app/main.py` 的 `build_detector()` 分支
3. 配置 `AI_DETECTOR_PROVIDER=mamba-yolo`、`AI_MODEL_PATH`、`AI_DEVICE=cuda`
4. 不改后端与前端；输出字段有新增则先改契约
5. 记录权重来源、验证范围与日期到问题记录

> 如果换模型需要改前端协议或表结构，说明占位抽象不合格，先修抽象层。

## 七、数据维护

| 数据 | 位置 | 保留 |
| --- | --- | --- |
| 告警与处置 | MySQL `alert` / `alert_action` | 不自动删 |
| 轨迹采样 | `track_sample` | 30 分钟 |
| 水质采样 | `water_quality` | 24 小时 |
| 推理指标 | `model_metric` | 24 小时 |
| 审计 | `audit_log` | 不自动删 |

清空演示数据：演示控制台「一键重置（含清空告警）」，或 `trigger.py reset`。
