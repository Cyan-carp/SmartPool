# 演示脚本与答辩提纲（8 分钟）

> 面向：课程答辩 / 项目验收 / 组内演示。**全程只演已实现的部分**，未实现项按「后续工作」表述。

## 一、演前 3 分钟检查

| 检查 | 动作 |
| --- | --- |
| 引擎 | `ssh home-dev schtasks /run /tn SmartPoolStartDocker`，等 60 秒 |
| 容器 | `docker --context home-dev ps --filter name=smartpool`，六个 healthy |
| 隧道 | `cd deploy\scripts; .\tunnel.ps1` 保持窗口 |
| 数据 | 打开演示控制台 → 一键重置（含清空告警） |
| 自检 | 六项状态卡全绿：推理正常、延迟 <1s、摄像头 4/4、水质正常、待处置 0、档位高峰 |

## 二、八分钟主线

| 时间 | 画面 | 讲什么 |
| --- | --- | --- |
| 0:00–0:40 | 登录页 → 实时监控 | 系统定位：辅助预警，不替代救生员；数据全部合成、模型占位 |

## 三、答辩口径（照读即可）

**一句话**：用合成数据把「检测 → 跟踪 → 时序风险 → 分级告警 → 人工处置 → 事件回溯」整条链路跑通，模型以占位实现接入，换真实权重不改上层。

**为什么模型是占位的**：权重与训练环境尚未就绪，业务侧不能等；占位实现能验证契约、时序、告警逻辑与界面，这些是演示主体。

**怎么换真实模型**：实现 `Detector` 接口 → 改 `AI_DETECTOR_PROVIDER` → 重启推理服务，前端与后端不动。

**和创新点的关系**：Mamba-YOLO、DeepSORT、Temporal Transformer、分时域调度属于研究目标；演示版只保留接口位置与展示位，不宣称精度与算力降幅。

**数据合规**：不采集真实影像与人脸，只用位置、姿态、区域等非身份标识；处置与配置变更全量审计。

**已知局限**（主动说，比被问出来好）：无真实精度；围栏未做米制标定；算力占比是模拟值；未做并发压测与公网部署。

## 四、常见追问与回答

| 追问 | 回答 |
| --- | --- |
| 误报怎么办 | 手环心率/血氧交叉验证 + 三级告警 + 误报标记回写统计，误报率在看板可见 |
| 一人多机位冲突 | 用 `track_id` 统一目标，手环与画面按编号配对；跨机位合并在 M2 之后的规划里 |
| 断网会怎样 | WS 指数退避重连，重连后拉快照对齐；推理不可用时画面冻结并提示降级 |
| 为什么不用 Kafka | 单机演示不需要；推理与告警已拆成独立进程，后续加消息队列不改契约 |
| 数据能复现吗 | 固定随机种子，重置两次目标集合一致（已脚本验证） |
